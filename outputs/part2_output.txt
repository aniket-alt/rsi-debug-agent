How to read this:
  * 'thrash/bug' = recurrences + opposing edits actually executed (wasted CI runs).
  * 'prevented'  = proposals SO-RSI blocked before spending CI on them.
  * 'naive + dedupe' isolates the cheap part (never retry); the gap to SO-RSI is the
    diagnostic part (symptom probe + opposing-edit block + inquiry memory).

==============================================================================
10.07  The three anomaly types and the diagnostic probe
==============================================================================
Anomaly            detection rule (on the patch trace)                 response
-----------------  --------------------------------------------------  ---------------------------
recurrence         same (patch, program state) evaluated again          block; probe symptom
opposing edits     proposed patch = inverse of last accepted patch      block; avoid oscillation
expectation mismatch  a proposed patch makes CI worse                   counted + negative evidence
(Every tried patch writes (symptom, operator, improved?) into the inquiry memory;
 mismatches are the negative evidence that lowers an operator's score for that symptom.)

The probe reads the CI failure and names a symptom class (cost: 2 test runs):
  exc       any test raised an exception          -> suspect ['ARITH', 'CONST_DN', 'CONST_UP']
  off1      every wrong output is off by exactly 1 -> suspect ['CMP', 'CONST_DN', 'CONST_UP']
  signflip  every wrong output = -expected         -> suspect ['ARITH']
  sparse    <=40% of tests fail                    -> suspect ['BOOL', 'CMP', 'EQ']
  dense     most tests fail                        -> suspect ['ARITH', 'BOOL', 'EQ']
These starting hypotheses are human-authored heuristics (the paper's 'lightweight probes').

What did the inquiry memory LEARN?  P(operator fixes | symptom), top 3 per symptom:
  symptom   operator    learned  trials   human hypothesis?
  exc       CONST_DN       0.72       9   agrees
  exc       CONST_UP       0.10       1   agrees
  off1      EQ             0.66      13   DISAGREES
  off1      CONST_DN       0.40     168   agrees
  off1      CONST_UP       0.10      20   agrees
  signflip  ARITH          0.71      33   agrees
  signflip  EQ             0.03       7   DISAGREES
  signflip  CONST_UP       0.02      11   DISAGREES
  sparse    CONST_DN       0.43      30   DISAGREES
  sparse    CMP            0.19      21   agrees
  sparse    ARITH          0.10       1   DISAGREES
  dense     EQ             0.46       6   agrees
  dense     CONST_DN       0.19     116   DISAGREES
  dense     ARITH          0.14     333   agrees

  -> 2 pairs with >2 trials and learned rate >0.3 that the human table did NOT predict.
     Inquiry memory lets observed evidence override the initial guess - but note the
     small-sample risk: 'off1/EQ' = 0.66 rests on only 13 trials.

Anomaly frequency in NAIVE traces on held-out bugs (10 seeds):
  recurrence  0.23 per bug   (18% of bugs hit it)
  opposing    0.42 per bug   (31% of bugs hit it)
  mismatch    1.90 per bug   (66% of bugs hit it)

FIXED SOURCE (SO-RSI):
def fizz(n):
    if n % 15 == 0:
        return 3
    if n % 5 == 0:
        return 2
    if n % 3 == 0:
        return 1
    return 0

Retrospective analysis (what the course asks in lab 10.08):
  * Did the naive agent repeat a patch?        recurrences = 0
  * Did it undo a previous change?             opposing    = 1
  * Did an outcome surprise it?                mismatches  = 4
  * What SO-RSI did differently: it probed the symptom, blocked every repeat, and never
    ran the oscillating CONST_UP/CONST_DN pair.  It did NOT get the ranking right
    at first: the memory's learned bonus for EQ (from few trials, see 10.07) outranked
    the probe's CMP/CONST suspects, so rounds 1-3 were wasted on EQ patches.  The
    blocking logic kept it from repeating them, and round 4 found the fix.

NOTE: this is one hand-picked illustrative bug (selected because it shows the
mechanism, including a weakness).  The honest numbers are the 10-seed table in 10.06.
