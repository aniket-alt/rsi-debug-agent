==============================================================================
Step 1. Collect 96 labelled patches on TRAINING bugs.
        label = how much the patch raises the visible-CI pass rate.
        96 patches  -> 25 improved CI, 15 made it worse, 56 changed nothing
        one-time labelling cost: 960 test executions

Step 2. Fit the linear readout   score = w . [parent_rate + 8 patch features]
        done (ridge regression, pure NumPy)

Step 3. Same agent loop, same budget (40 test runs/bug), only the SELECTOR differs.
        All use: accept only strict CI improvement, never re-run a tried patch.

10.04  Analyse the scoring mechanism
==============================================================================
Learned coefficients (largest magnitude first):
   op=CMP         +0.811
   op=BOOL        +0.775
   op=ARITH       +0.667
   parent_rate    -0.662
   op=CONST_DN    +0.628
   op=EQ          +0.625
   rel_line       -0.561
   op=CONST_UP    +0.501
   ochiai         -0.029

Reading: operator type carries the signal; 'ochiai' (fault localisation) is ~0.
That is a finding, not a bug: with only 25 improving patches in 96, a LINEAR model
on one-hot operators learns 'which patch KINDS tend to help', not 'where the fault is'.

Ablation A - drop features (held-out fix rate, k=1, 10 independent fit seeds):
   all 9 features             fixed  41.9%  (+/-5.5 across fits)
   no ochiai/rel_line (7)     fixed  34.4%  (+/-4.7 across fits)
   ops only, no parent (6)    fixed  35.3%  (+/-5.4 across fits)
   parent_rate only (1)       fixed  31.0%  (+/-0.0 across fits)

Ablation B - number of labelled patches (k=1, 10 fit seeds each):

==============================================================================
10.05  Extend: does the scorer rank a VALID fix highly on unseen bugs?
==============================================================================
For every single-fault held-out bug: score all candidate patches (zero CI runs) and find
where the FIRST patch that really fixes the bug (passes the hidden tests) lands.
(Several patches can be valid fixes, so we do not require the exact injected inverse.)

single-fault held-out bugs: 27
valid fix ranked #1 : 5/27 = 19%
valid fix in top-3  : 9/27 = 33%
mean rank of first valid fix: 7.19   (random order expectation 7.94)
-> the one-shot ranking edge is small; the end-to-end gain comes from it compounding over rounds.

Where does the end-to-end gain come from? Fix rate by held-out function (k=1, 10 seeds):
   function        random  readout
   abs_diff_sum       40%      70%
   fizz               15%      24%
   gcd                70%     100%
   inversions         52%      60%
   leap                7%       5%
   (the scorer helps on some functions and does nothing - or slightly hurts - on 'leap')

Worked example (one held-out bug): predicted score vs actual CI gain
def inversions(xs):
    c = 0
    for i in range(len(xs)):
        for j in range(i + 1, len(xs)):
            if xs[i] >= xs[j]:
                c += 1
    return c

HONEST LIMITS: operator priors transfer across functions, localisation does not help
in a linear readout, and the 96-patch fit is a real cost.  The gain over random is
modest and uneven; it is not the paper's headline number (different task and scale).
